# Saved answer ancestry

`GET /fri/contract` advertises `saved-answer-ids`. Saved context turns expose `answer_id`: the delivered Discord reply ID, or a stable random `turn:` identity when no delivered ID was recorded. Fri sends optional `carried_answers` on `/chat/turn` only with that capability, accumulating identities after withholding at every model request. These identities are metadata, never model instructions.

Gene records exact structural ancestor links, including ancestors of answers carried from saved history. Withdrawal retires those descendants while preserving a turn that saw only the question. Existing `drew_on` semantics remain. Both lookups use indexed tables; SQLite triggers maintain and clean links under older controller writes too. Ancestry never matches reply words. Upgrade classification recognizes only exact controller-owned retirement markers with `verbatim=0`; the context exposure path repeats that guard even if a lifecycle flag is stale. Existing retirement breadcrumbs are backfilled before any answer identity is exposed.

Bounds: 1,000 ancestors per turn, depth 64, and 10,000 tracked turns per guild. A valid save exceeding a bound returns success with `kept: false`; it cannot leave a partly tracked saved reply. An invalid or missing optional field is ignored completely, retaining prior behavior. These bounds apply to the new ancestry; legacy `drew_on` behavior is preserved. An answer also inherits the original message dependencies of the answers it actually carried, in a separate indexed table, so trimming a middle exchange does not break withdrawal. This set keeps the newest 100 IDs (as Fri ancestry does), marks overflow unknown and propagates that marker. Unknown exchanges retain their question and a neutral breadcrumb, expose no answer identity, keep no pending clarification and cannot be reused as verbatim reference answers; older readers also see the breadcrumb. A question-only turn inherits neither the set nor its unknown marker.

The migration is additive and uses SQLite 3.40.1-compatible SQL. Old Fri omits metadata. Old Gene ignores the optional field. Rollback preserves retired breadcrumbs and new tables; old writers' deletes and inserts remain compatible. During rollback, new ancestry is not recorded by old Gene. Delayed saves after a retirement retain the pre-existing limitation noted in #267. Gene must merge and deploy before the paired Fri change.

Correction-round proof: upgrade regressions for summary, withdrawal and erasure retirement, including a deliberately stale lifecycle flag; six-turn trimming with an independent question-only control; inherited-set overflow/unknown propagation; index/cleanup checks; and an actual synthetic database created and retired by `29d6791`. The first four new regression cases fail at the round-1 head.
